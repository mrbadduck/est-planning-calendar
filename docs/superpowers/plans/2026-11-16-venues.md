# Venues Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Leads can add a venue and fix a venue's address from the event's Where block; addresses are stored as Street/Unit/City/State/ZIP and sent to Eventbrite as exact fields.

**Architecture:** One pure shared module (`web/venue-address.js`, bundled into the Worker like `listing-readiness.js`) owns compose/validate/has-address rules. The Worker gets three role-gated routes (`GET/POST/PUT /venues`) whose request→cells logic lives in a pure, tested `proxy/src/venues.js`; `worker.js` only wires them. The app adds an inline venue form in the Where block, waits for Coda to apply each write (D3), then selects/updates the venue. A one-off script backfills the five columns from the old `Address` text after Eric approves a dry run.

**Tech Stack:** Vanilla JS (buildless), Cloudflare Worker (ES modules), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-16-venues-design.md`

## Global Constraints

- Branch `feat/venues` in `.worktrees/venues`, stacked on `feat/event-page` (PR #38); PR base `feat/event-page`.
- D1 stable containers + `paintInner`, no `outerHTML`; D3 Saved = applied (`CodaApplied` / `waitApplied`); D7 no silent fallbacks; buildless; `web/*.js` ≤ 800 lines; `web/listing-readiness.js` and `web/venue-address.js` DOM-free (Worker-bundled).
- New Coda reads/writes by column id from `proxy/src/coda-columns.js`. Every venue write busts KV `ref-venues-v2` (bump the key if the projection shape changes).
- Role gate: `canWrite` (Program Lead or Tribal Council) for all three routes.
- **R1:** no live writes during the build — no deploys, no Coda/Eventbrite writes; tests mock `fetch`; browser checks stub non-GET requests. Exceptions only with Eric's explicit OK in chat: (a) adding the five columns, (b) the backfill `--write`.
- Help ships with the change; help guard must pass. Tests under the machine-wide lock. Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Exact on-screen labels (from the spec): **+ Add "<name>" as a venue**, **Add venue**, **Cancel**, **Adding venue…**, **Edit address**, **Add address**, **No street address yet**, **Save address**, "This changes the address for every event at this venue."

## Review Focus

1. A private home's address must never reach the shared `/ref/venues` list, and Registrants-only events must still send Eventbrite only the coarse area (`venuePayload` safety split).
2. Duplicate names (case/space-insensitive, e.g. "the basement" vs "The Basement ") are refused.
3. An address change must clear both cached Eventbrite venue ids, or Eventbrite keeps the old address.
4. The event must not point at a venue row Coda hasn't applied yet: create → wait applied → select.
5. Old rows without structured fields keep working (parse `Address` as today) until backfilled.

### Task 1: Shared address rules — `web/venue-address.js`

**Files:** Create `web/venue-address.js` (IIFE on `globalThis.VenueAddress`, like `listing-readiness.js`); Test `proxy/test/venue-address.test.js`; Modify `web/index.html` (load after `listing-readiness.js`); the Worker imports it for side effects where it needs it.

**Produces:**
- `normalize(a: {street,unit,city,state,zip}) → same shape` — trims, collapses spaces, uppercases state.
- `compose(a) → string` — `"Street, Unit, City, ST ZIP"`, omitting empty parts (`"12 Main St, Nashville, TN 37206"`; with unit `"12 Main St, Apt 2, Nashville, TN 37206"`).
- `validate(a, {allowBlank:boolean}) → {ok:boolean, errors:{street?,city?,state?,zip?}}` — blank allowed only when `allowBlank` and every field empty; otherwise Street, City required, State = 2 letters in the US set, ZIP blank or `^\d{5}(-\d{4})?$`. Messages: "Add the street", "Add the city", "Use the 2-letter state (e.g. TN)", "ZIP is 5 digits".
- `hasAddress(v: {street,city,address}) → boolean` — structured Street+City, else non-blank legacy `address`.
- `sameName(a,b) → boolean` — case-insensitive, whitespace-collapsed equality.

- [ ] Tests first (each function, the examples above, a Home with all-blank + allowBlank → ok, partial address → errors), run → FAIL, implement, run → PASS, `./scripts/check.sh`, commit `feat(venues): shared address rules`.

### Task 2: Columns + Worker routes

**Prerequisite (controller):** Eric has OK'd adding the five text columns (`Street`, `Unit`, `City`, `State`, `ZIP`) to `EST Venues SRC`; the controller adds them and records their ids in this task's dispatch.

**Files:** Modify `proxy/src/coda-columns.js` (venue column ids: Venue Name `c-qOEGjzi8TZ`, Address `c-19lFeKZu_W`, Venue Type `c-Yqz2FaSKTR`, Eventbrite Venue ID `c-8q1sI7FT2R`, Eventbrite Private Venue ID `c-KPZs1NHQFF`, Closed/Unavailable? `c-ZWCo5eGocY`, plus the five new ids); Create `proxy/src/venues.js` (pure); Modify `proxy/src/worker.js` (routes), `proxy/src/publish.js` (`venueRefItem.hasAddress` via `VenueAddress.hasAddress`), `proxy/src/eventbrite.js` (`venuePayload` structured path); Test `proxy/test/venues.test.js`, extend `proxy/test/publish.test.js`/`eventbrite.test.js`.

**Produces (`proxy/src/venues.js`):**
- `venueFromRow(row) → {id,name,type,street,unit,city,state,zip,address}` (by-id values).
- `createCells(body, {venues, types}) → {cells}|{error,status}` — 400 missing name / bad type / invalid address; 409 duplicate name ("A venue called X already exists"); cells include the five fields + composed `Address`.
- `updateCells(body, row) → {cells}|{error,status}` — address fields + composed `Address` + blank `Eventbrite Venue ID` and `Eventbrite Private Venue ID`.
- Routes: `GET /venues/:rowId` (canWrite) → `venueFromRow` minus EB ids; `POST /venues` → insert, return `{id, requestId}`; `PUT /venues/:rowId` → update, return `{requestId}`; all writes bust `ref-venues-v2`. Unknown row → 404. Not authorized → 403.
- `venuePayload(venue, visibility, area)` accepts `{name, street, unit, city, state, zip, address}`: public + structured → `address_1=street`, `address_2=unit`, `city`, `region=state`, `postal_code=zip`; otherwise today's parse path. Registrants-only unchanged (coarse area, generic name).
- `ensureEbVenue` passes the structured fields; `hasAddress` checks use `VenueAddress.hasAddress`.

- [ ] Tests first: `createCells` (ok, missing name, duplicate with different case/spacing, bad type, partial address, Home blank ok), `updateCells` (clears both EB ids, composes Address), `venuePayload` structured public / structured registrants-only (no street leaks) / legacy parse, `venueRefItem.hasAddress` both shapes; route wiring tests if the harness supports invoking the Worker fetch handler with mocked fetch (follow existing tests' pattern), else keep wiring trivial. Run → FAIL → implement → PASS (full `npm test`), commit `feat(proxy): venue routes and structured addresses`.

### Task 3: Backfill script (dry run only)

**Files:** Create `scripts/backfill-venue-address.mjs`.

- Reads `EST Venues SRC` by id (token from `proxy/.dev.vars` `CODA_API_TOKEN`; never printed), parses each row's `Address` with `parseUsAddress`, validates with `VenueAddress.validate`, prints a table `row id | name | Address → Street | Unit | City | State | ZIP | OK/FLAG(reason)`; skips rows whose Street is already filled. `--write` writes only rows marked OK (sets the five fields; leaves `Address` and EB ids untouched); refuses to run `--write` without `--yes`.
